G1 Port Audit

Why each Unitree G1 walking policy in rhoyn's teleop-walking-benchmark scores what it does. Each port was read from its own adapter code, then the benchmark's 90 s waypoint tour was run one change at a time: the policy as its authors configured it, the port's values, the harness taking the arms, the random arm walk, the punches.

Since the last audit

  • The first audit ran at benchmark commit 6d331a8. There, schoi lost 85 s between its authors' config (90 s) and the port's values (4.7 s): the port contract held its waist at kp about 28, against 300 in the authors' config. The harness now holds every leg and waist motor at the policy's own gains (rhoyn/teleop-walking-benchmark@4ed23c2), and what stops schoi now is the punches.
  • The same harness fix moves zealot in the benchmark from 8.2 s to 67.6 s. zealot is now read too: it observes the action from two steps back, joint velocities by difference, a gait clock whose period follows the command speed, and a command it steers itself toward the waypoint.
  • nanog1 (right hip roll clamp) and homie (history start) were corrected upstream. nanog1 and wcompton, unclear in the first audit, now run their authors' configs (nanoG1's deploy_g1.py; the checkpoint's own metadata for wcompton): both fall within 4 s under them, so their scores belong to the policies, not the ports.
  • Thirteen more ports and variants are read, each rebuilt to 1e-6 or better on random inputs: decoupled_wbc and gr00t_wbc (four variants each; gr00t_wbc switches between its walking and balance networks by the command), homie, falcon, openwbt, asap and handoff; and holosoma's observation now matches its adapter. What they needed: observed joints no action drives, the harness's arm targets, commands a port steers or gates itself (by distance, by a walk latch, by size, after a warm-up), gait clocks that stop or warp, and layouts no single history window describes.
  • Every stage now runs 10 seeds (3 before), and seed n is the benchmark's run n: the tour, the arm walk and the punches draw from the benchmark's own random streams, so each run here pairs with the same run there. The punches now land as the benchmark's do (at the joint's anchor, in a direction that turns with the link), the arm walk redraws a target that puts a hand behind its stance position or above the head, and every run starts as the benchmark's do (3 s on a crane at the harness's stance, then let go) and ends when the pelvis is below 0.2 m.

How to read a verdict

Every runSeed n draws the benchmark’s run n: its waypoints, arm targets and punches, from its own random streams. A run starts as the benchmark’s do, 3 s on a crane at the harness’s stance and then let go, and ends when the pelvis is below 0.2 m. Authors' configThe policy as its authors trained or deployed it: their gains, poses and observation, read from their config (Isaac Lab env.yaml, unitree_rl_gym, a Unitree deploy.yaml). Run with the same drive as the port, so stages differ only in values. Port's valuesThe values the benchmark's adapter feeds and applies, with the policy driving every joint it lists. Harness holds armsThe harness takes the arm joints from the policy and holds them at its stance with its own gains. Random arm walkThe harness moves the arms at random, as teleoperation does. Plus punchesA punch on a random link every waypoint, rising to 500 N. Port, full benchmarkAll of the above with the port's own view of the arms (some ports hide arm motion from the policy). Bench, HereMean survival over runs 0–9: the benchmark’s MuJoCo numbers for those run ids, and the port under the full benchmark here on the same draws. A row’s run table marks a run here or in the benchmark’s PhysX that ends more than 1 s from the benchmark’s MuJoCo run.

Evidence L1: one runner, one model, stated assumptions. A verdict names the step that costs survival here; it is not a claim about the benchmark's own numbers, and a step that is not run cannot be blamed.

Reproduce

pip install "gaitkeeper[sim]==0.5.2"
git clone https://github.com/rhoyn/teleop-walking-benchmark twb   # at 106faa0

git clone https://github.com/unitreerobotics/unitree_rl_gym   # rl_gym's authors' config

# read a port from its adapter (needs g++ or clang++); a port with variants reads each
gaitkeeper adapter twb/policies/rl_gym/policy.cpp --mjcf twb/assets/g1_29dof.xml --out contracts/
gaitkeeper adapter twb/policies/gr00t_wbc/policy.cpp --mjcf twb/assets/g1_29dof.xml --out contracts/

# run the ladder, with the authors' config as the first stage when there is one
gaitkeeper bench --adapter twb/policies/rl_gym/policy.cpp --onnx twb/policies/rl_gym/model.onnx \
    --upstream unitree_rl_gym/deploy/deploy_mujoco/configs/g1.yaml \
    --mjcf twb/assets/g1_29dof.xml --seeds 10 --md rl_gym.md

# a variant, by name (its models are found next to the one given)
gaitkeeper bench --adapter twb/policies/gr00t_wbc/policy.cpp --variant gr00t_wbc_h066_p012 \
    --onnx twb/policies/gr00t_wbc/model_walk.onnx --mjcf twb/assets/g1_29dof.xml --seeds 10

Source, method and every command: github.com/dundysm/gaitkeeper.

Interactive: command dead zones of the unitree_rl_lab G1 policy, drag the command and watch it stand or walk.

Run it on your own policy

The same checks on a G1 policy whose config gaitkeeper reads, in one to two and a half minutes on a laptop:

gaitkeeper doctor --onnx policy.onnx --config <your config> --mjcf scene.xml

The config is read by content: an Isaac Lab env.yaml, a Unitree deploy.yaml, a unitree_rl_gym or legged_gym config, or a contract. Doctor reports the contract fields no file states, the commands the policy ignores, and survival on the tour with the arms its own, moved at random and punched.
